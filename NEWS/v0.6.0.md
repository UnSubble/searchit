# Searchit v0.6.0

Release Theme: Dry-Run Preview, Smarter Fuzzing & Reliability

Searchit v0.6.0 delivers two major workflow improvements — `--dry-run` preview for both `scan` and `fuzz` commands — alongside more precise fuzz output formatting, secondary-placeholder alias resolution, empty-extension support in `-e/--ext`, and substantial internal reliability and connection-reuse improvements.

### Added

- **`--dry-run` / `--dry-run-limit` for `searchit fuzz`** — renders the complete candidate list without sending any network requests. Uses the identical candidate-generation pipeline as the live run (same placeholder expansion, alias resolution, Cartesian-product ordering, and `RequestDTO` construction), so candidate #N in dry-run is guaranteed to match candidate #N in the real execution.

- **`--dry-run` / `--dry-run-limit` for `searchit scan`** — previews scan candidates (wordlist words + extension variants) at depth 1 without performing any network I/O, including the HTTP auto-detection probe. The preview uses the same `DirectoryGenerator` iterator as the real scan, guaranteeing candidate-order parity.

- **Empty extension sentinel in `-e/--ext`** — a leading, trailing, or internal comma now explicitly includes the extensionless base word as a candidate:
  - `-e ",php,html"` → `test`, `test.php`, `test.html`
  - `-e "php,html"` → `test.php`, `test.html` (no base word)
  - Duplicate entries and consecutive commas are deduplicated; no trailing dot is ever produced.

- **Alias resolution for secondary placeholder wordlists** — `FOO`, `BAR`, `BAZ`, and `BUZZ` now accept `=fuzz`, `=foo`, etc. to reuse a previously loaded wordlist without reopening the file. Alias cycles and references to unloaded wordlists produce a clear validation error at startup.

- **`httpclient.DrainAndClose`** — a bounded (64 KiB) response body drain helper that always closes the body, enabling HTTP/1.1 connection reuse across scan, fuzz, adaptive discovery, robots.txt fetching, and auto-detection probing.

- **`wordlist.LoadEffectiveWords`** — unified loader that transparently reads from a file path or the embedded default wordlist, removing caller-side branching.

### Changed

- **Fuzz finding output** — findings from `searchit fuzz` now show a compact, placeholder-aware block grouping the URL, matched header values, cookie values, and body payloads under clear section labels (`URL`, `Header`, `Cookie`, `Body`), making multi-location placeholder results immediately readable.

- **`FUZZ CONFIGURATION` block** — per-placeholder entries now include location, source file, entry count, and an alias label when a secondary placeholder reuses another wordlist.

- **Progress terminal output** — `ExecuteAbove` now routes all output (ANSI clear, finding text, ANSI redraw) through a single TM-locked writer, eliminating stdout/stderr interleaving on real TTYs.

- **`FrontierPending` metric removed** — this internal field was never surfaced in user-visible output; its removal simplifies the stats model.

- **HTTP client construction** — refactored to use a structured `Options` value instead of positional arguments.

- **`recursion.Manager.Run`** — accepts an optional `onRootError` callback for structured root-request failure handling instead of silently swallowing errors.

### Fixed

- CI: corrected an invalid commit SHA for the `upload-artifact` action in the benchmark workflow.
- CI: `staticcheck` now installs from `@master` to support Go 1.27's export data format (v4), resolving the "export data version 4 is greater than maximum supported version 2" lint failure.

### Testing / Internal

Significantly expanded test coverage across the codebase:

- Table-driven unit tests for the adaptive engine (`prioritizer`, `selector`, `signals`, `summary`, policy).
- Profile schema decoder, type, scan/fuzz validator, and importer unit tests.
- Configuration, diagnostics, telemetry, target parser, and command-execution utility tests.
- `stats.Collector` invariant tests (progress bounds, monotonicity, conservation, concurrent safety).
- Output formatter and progress manager invariant tests.
- `httpclient.DrainAndClose` unit and benchmark tests (small, boundary, oversized, unknown-length, redirect cases).
- `wordlist.LoadEffectiveWords` tests (file-backed and embedded fallback).
- Extended `state`, `env`, and profile importer test coverage.
