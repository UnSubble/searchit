# Searchit v0.6.1

Release Theme: Fuzz URL Template & Extension Fixes

Searchit v0.6.1 is a patch release addressing template truncation bugs in multi-level fuzzing traversals, fixing empty-extension sentinel handling on the CLI, and correcting candidate count estimation.

### Fixed

- **Fuzz URL template truncation in multi-level traversals** — fixed an issue in `TruncateTemplate()` where evaluating placeholders in multi-level traversals (DFS, BFS, Priority, Adaptive) could prematurely truncate the template at or before the current depth's placeholder. Templates with static prefixes (e.g. `http://example.com/hmr_FUZZ/FOO`) now correctly retain the current level's placeholder and prefix without truncation.
- **Empty extension sentinel with CLI `-e/--ext` flag** — fixed `extensions.Parse()` dropping empty string tokens produced by pflag's comma-splitting on flags such as `-e ",php"`. The extensionless variant (e.g. `test`) is now properly preserved alongside extension variants (e.g. `test.php`).
- **Candidate count estimation overcounting** — adjusted total candidate estimation in `cmd/fuzz.go` and `cmd/scan.go` from `(1 + len(exts))` to `len(exts)` to match `GenerateVariants` semantics where the extensionless variant is an explicit entry in the extensions list.

### Testing / Internal

- Added regression tests in `internal/fuzz/url_substitution_test.go` verifying that embedded prefixes and static content around `FUZZ` (such as `/hmr_FUZZ`, `/api/FUZZ/test`, and `/prefix_FUZZ_suffix`) are preserved during template compilation, rendering, and multi-level truncation.
- Added regression tests in `internal/extensions/extensions_test.go` verifying pflag-split comma behavior for empty sentinels and round-trip candidate generation.
